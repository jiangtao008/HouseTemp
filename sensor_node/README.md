# Sensor Node — ESP32-C3 温湿度传感器节点

基于 ESP32-C3 (Mini) 的 BLE 温湿度广播节点，使用 SHT40 传感器采集数据，通过 NimBLE 广播传感器数据包。

## 硬件

| 组件 | 说明 |
|------|------|
| MCU | ESP32-C3 (Mini 开发板) |
| 传感器 | SHT40 (I2C, 地址 0x44) |
| I2C | SDA=GPIO4, SCL=GPIO5 |
| 供电 | 锂电池 → TP4056 充电板(带保护) → 开发板 5V/VIN，持续供电 |
| 配置模式 | 无硬件开关，冷启动自动进入，5s 无命令超时退出 |

## 供电与电池检测

### 供电拓扑

```text
锂电池 ── TP4056 充电板(带 DW01A 保护) ── OUT ── ESP32-C3 开发板 5V/VIN
                                                   │
                                              板上 3.3V 稳压器 ── ESP32-C3
```

- 锂电池通过 TP4056 充电板连接，充电板负责**充电管理 + 过放/过流/短路保护**（DW01A + 双 MOSFET）
- 充电板 `OUT` 直接接开发板 `5V/VIN` 引脚，**一直给节点供电**（电池电压范围约 3.0~4.2V）
- 开发板上的 3.3V 稳压器把输入降到 3.3V 供 ESP32-C3 使用
- 不充电时 `OUT` ≈ 电池电压；充电时 TP4056 恒压段把电池钳在 ~4.2V

### 可用电压区间

- 电池满电 4.2V，放电下限由**板上稳压器的压差**决定
- 本板（`esp32-c3-devkitm-1`）使用低压差 LDO（ME6211 类，压差约 0.1V），电池 ≥3.4V 可稳定输出 3.3V；低于该值节点会掉电/复位
- 若换用 AMS1117 类（压差约 1.1V）的板子，电池低于 ~4.4V 就无法稳压，**不能直接用于此供电方案**
- 软件侧放电截止应取 ~3.4V，而不是等到 DW01A 过放保护（~2.4V，此时稳压器早已掉电）

### 电池电压采样（尚未启用）

当前 `BATTERY_ADC_PIN = -1`，广播包里的 `battery_mv` 为占位。启用前需满足：

- C3 ADC 满量程约 2.5V(0dB) / 3.1V(11dB)，**不能直接量 4.2V**，必须分压
- 取样点接 `OUT`（= B+，即电池正极），量到的就是电池电压；建议 **100K:100K** 分压（÷2，4.2V→2.1V）接 C3 的 ADC1 引脚（GPIO0~4）
- 充电时采样值会被钳在 ~4.2V，无法区分"正在充电"与"真满电"，属测量固有歧义
- 分压支路常接会带来约 21µA 静态电流（对 60s 深睡场景占比明显），建议用 **MOSFET 仅在采样瞬间导通**分压支路，降低静态功耗

## 烧录指南

### 进入下载模式

ESP32-C3 上电/复位时会检测 **GPIO9 (BOOT 按钮)** 的电平状态：

| GPIO9 电平 | 模式 |
|------------|------|
| 低电平 (按住 BOOT) | **下载模式** |
| 高电平 (不按 BOOT) | 正常启动 |

**手动进入下载模式的按键顺序：**

```
1. 按住 BOOT 按钮（不要松手）
2. 按一下 RESET 按钮（然后松开）
3. 松开 BOOT 按钮
```

> 成功进入下载模式后，PlatformIO 的 esptool.py 即可识别并烧录。

**烧录完成后：** 按一下 **RESET** 按钮，程序正常启动运行。

> PlatformIO 上传时会通过 DTR/RTS 信号尝试自动复位进入下载模式，有时候可以直接成功；如果自动方式失败，用手动按键方式成功率 100%。

### PlatformIO 命令

```bash
# 编译
platformio run

# 烧录
platformio run --target upload

# 串口监视器 (115200 baud)
platformio device monitor -b 115200
```

## BLE 广播协议

传感器节点以 **不可连接广播 (Non-connectable advertising)** 方式发送数据包，结构如下：

```cpp
struct __attribute__((packed)) SensorPacket {
  uint8_t  protocol_ver;   // 协议版本号
  uint16_t device_id;      // 设备 ID
  uint32_t counter;        // 数据包计数器
  int16_t  temperature;    // 温度，单位 0.01°C (×100)
  uint8_t  humidity;       // 湿度，单位 %
  uint16_t battery_mv;     // 电池电压 (mV)
  uint32_t auth_tag;       // HMAC-SHA256 认证标签 (取前 4 字节)
};
```

### 串口日志格式

```
ID=<device_id> C=<counter> T=<temp_°C> H=<humi_%> B=<battery_mV> TAG=<auth_tag_hex>
```

## 认证

数据包使用 **HMAC-SHA256** 进行完整性认证，密钥在 `config.h` 中配置。网关收到数据包后应使用相同的密钥重新计算认证标签进行校验。

## 配置模式

节点在**冷启动**（上电 / 按 RESET）时默认进入配置模式，用于在不重新烧录的情况下修改节点 ID 和节点名。无需硬件开关。

| 冷启动后的行为 | 说明 |
|------|------|
| **5s 内收到任意串口命令** | 一直保持配置模式，直到下次冷启动 |
| **5s 内无任何串口命令** | 自动退出配置模式，进入正常低功耗流程（上报温湿度 + 深睡） |

配置窗口时长由 `CONFIG_MODE_WINDOW_MS` 配置（默认 5000ms）。

### 进入配置模式

1. 给节点上电 / 按 RESET
2. 在 5s 窗口内打开串口监视器（USB-CDC `Serial` 与 UART0 `Serial0` 均可，115200 baud）
3. 发送任意命令（如 `show`），节点保持配置模式，出现提示符 `> `

### 串口命令

| 命令 | 说明 |
|------|------|
| `help` / `h` | 显示命令列表 |
| `id <1..65535>` | 设置并持久化节点 ID |
| `name <文本>` | 设置并持久化节点名（最长 32 字符） |
| `show` | 显示当前配置 |
| `reset` | 清空已保存配置，恢复默认 |
| `reboot` / `exit` | 退出配置模式并重启（进入正常低功耗流程） |

配置写入后**立即持久化到 NVS**，重启后生效。

### 退出配置模式

- 串口发送 `reboot`（或 `exit`）；或
- 不发送任何命令，等待 5s 超时自动退出；或
- 按 RESET 重新冷启动（若仍无命令，5s 后自动进入正常流程）

> 注意：修改节点 ID 后，需同步更新网关的节点名表
> [`ble_gateway/src/config.h`](../ble_gateway/src/config.h)（`NODE_NAMES`）
> 以及服务端数据库中该节点的名称，网关面板才会显示正确的名称。
